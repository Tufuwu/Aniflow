# 《成为伯爵家的废物》衔接材料撰写规则

衔接材料供下一话写稿使用，只回答三个问题：**观众已经知道什么、本话具体停在哪里、哪些问题还悬着。** 撰写时把下一话视为未知，不查阅、不引用、不推测后续内容。

## 先确定依据

1. **以指定成片为准。** 对照成片、实际使用的最终口播稿和导出记录；不要只凭版本号最大的稿子判断。镜头、字幕和实际口播不一致时，分别记录观众看到和听到的内容；影响衔接的差异应注明，不自行补写。
2. **对照上一话衔接资料。** 只带入本话仍有效的目标、关系和未解事件。旧资料用来确认观众已知范围，不用来替代本话实际进展。
3. **只核对到本话为止。** 即使下一话素材已经存在，也不提前查看或写入衔接材料。实际写下一话时，再依据那一话的正文决定怎么接。

## Markdown 简报怎么写

- **标题与版本：** 用「第 N 话《标题》成片衔接资料」，明确漫画话数、视频集数、素材编号和所依据的口播版本。三种编号分开写，不凭文件夹编号推断话数。
- **可直接沿用的前情：** 用一两段概括人物目标、关键行动和本话实际进展。重点写下回开头必须知道的信息，不复述全部镜头。
- **成片已交代的内容：** 按最终口播稿的自然段编号分组，列「口播段落」和「观众已知」。合并相邻的同一事件，保留推动下一话的因果、名字和关键对白。
- **人物和章末状态：** 写明人物最后的位置、已知关系、手上资源、未完成的打算，以及是否见面、具名、获得能力。未出场的人只在与下话相关时补一条，标明是沿用前情。
- **精确停点与待承接问题：** 记录末镜动作、末句原文和未兑现的悬念。可以附一到两句只回顾本话的衔接备选，不指定下一话开场、不预写结果。

## 事实与口径

- **区分事实来源。** 分清当下发生、开场预叙、书中书的记载、传闻、人物的猜测或计划。未在本话发生的事，不计入本话进展。
- **不提前揭晓。** 能从项目设定认出人物，不代表观众已知道其姓名、种族或能力。示意图不等于事件发生，人物的估计也不等于确定条件。
- **保留成片口径。** 用当前成片采用的译名和对白。原著可帮助理解背景，但不能补进成片没交代的结果。例：第 3 话停在凯尔倒面包，只记「倒完后的结果未交代」，不写洞后来怎样或是否拿到盾。

## 文件与交接

1. 在 `continuity/` 下保存 `第N话_成片衔接资料.md` 和 `episode_素材编号_memory.json`。沿用现有 JSON 结构：`schema_version`、视频集数 `episode`、漫画话数 `comic_chapter`、来源章节、源稿版本及 SHA-256、段落数、成片路径、摘要、分段事件、未决事项与 `ending`。不新增 `next_opening`；待承接的问题写进 `unresolved`。
2. 成片口径确定后，再更新 `continuity/latest.json`，指向此话的简报、记忆文件和源稿，并填写一致的素材编号、视频集数及源稿哈希。只有草稿时标明暂定，不替换当前的成片索引；补写旧话时也不把索引倒退。
3. 交付前确认：JSON 能解析；索引文件及引用的路径存在；源稿哈希与导出记录一致；自然段从 1 开始编号，分段范围不越界；末句和停点与成片相符；没有写入任何后续情节。历史话的简报和记忆文件保留。
