# 故事吸引力改造与离线验收

目标是让故事持续推进。篇幅由必要的动机、阻碍、转折、行动与兑现决定，不以总时长、固定节点数或每段字数压缩剧情。没有观众留存数据时，自动检查只能验证叙事约束，不能证明真实观看留存。

## 已实现

1. **完整画面准备**：扩大检测窗口，移除落在完整检测框内部的阅读边界；按自然留白组织相邻小片段，不在固定高度截断画面。仅压缩 RGB 全为255的纯白行，保留未压缩来源图、哈希和保留行映射。
2. **整话叙事规划 v5**：一个节点可包含多个来源事件；规划需明确关键动机与转折，并由独立的剧情完整性复核检查遗漏。旧 `max_events` 参数仅作兼容输入，不再限制节点数量。旧版本剧情与审核数据仍可读取。
3. **整稿写作**：先一次生成完整口播稿，再检查连贯性、重复、称呼、转折和兑现。逐句事实核验继续读取原图；`issues` 和 `uncertain` 均会触发有反馈的重新生成。修正后再次复核全稿。
4. **证据和展示分工**：节点内全部主事件参与画面覆盖；递归因果前提仍保留于事实证据中，但新版节点不会被迫逐一重放所有旧因果画面。历史单事件节点保持原来的覆盖约束。
5. **看图选镜和裁切复核**：选镜模型收到真实候选图片；已选裁切会再次送入视觉复核，被拒绝的局部裁切恢复完整来源后重新检查。仍有问题的结果保持待审核。人工锁定的镜头组合不被 AI 重跑改写。
6. **版式与导出**：字幕采用明确的1080×1920 ASS画布、52像素字号和底部安全区；按标点断句，普通英文词不从中切断，超长词仍按安全长度分割。画面保留字幕区，运动使用放大后采样。导出继续完整解码验证，并报告纯白占比过高的镜头。
7. **待审核预览入口**：增加 `story_app.py preview`，使用项目现有组件生成独立预览，不修改人工审核状态。`--offline` 强制使用已有音频缓存、关闭模型选镜，缓存缺失即报错，不退回在线配音。

## 使用

在线生成（本轮未执行新版整稿在线生成）：

```powershell
python story_app.py run --project <独立项目名> --style faithful
```

只使用缓存的离线预览：

```powershell
python story_app.py preview --project <已有草稿项目> --output <已有配音缓存的目录> --rate=+25% --offline
```

运行离线测试时可将 socket 连接替换为直接报错，确保任何意外网络请求都会让测试失败；本轮验收即使用此方式。新增测试文件本身也安装了禁止网络的 fixture。

## 仍需真实模型验证

- 新版规划是否稳定发现每话真正的动机、反差和转折。
- 整稿是否自然、连贯，修正后是否仍保留关键剧情。
- 新分镜边界和模型建议裁切在真实漫画中是否语义完整。
- 视觉复核对主体截断、空镜和不匹配镜头的识别效果。
- 最终观看节奏和持续观看意愿。

当前 DeepSeek 配置保持不变：仅 `check` 逐句事实核验开启低档思考，其余 Story 阶段关闭思考。没有为本轮离线验收新增模型或配音 API 调用。
