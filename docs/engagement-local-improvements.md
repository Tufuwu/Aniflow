## 根因与实际产物

## 本地实现

1. `semantic_grounding.py` / `fact_checker.py`：逐句可拆成自然语义单元，保留原文区间、实际讲述的 `event_ids`、展示 `display_panel_ids`、仅用于核验的 `background_event_ids`。严格检查原文完整覆盖、事件范围、每个讲述事件的展示来源。原图仍参与严格事实核验。关联与文本、事件记录及来源哈希绑定，旧核验没有该字段时明确为待检查。
2. `shot_selector.py`：有有效逐句关联时，只从当前单元的展示来源中选镜，包括实际被讲述的上下文事件；不机械播放未被讲述的递归背景。每个所选镜头关联 `unit_ids`；裁切复核收到对应原句，不能仅凭整段提到过事件判通过。人工锁定镜头不被自动改写。
3. `tts_engine.py`：Edge 连续合成同一段时，从同一次流中保存词边界、文本哈希与音频哈希；取消以前为字幕再次请求配音的路径。保留现有中文音色和调用者语速，不做逐字合成。已有实测语义段时间继续复用；中断的音频流不能伪装成成功缓存。
4. `timeline_director.py`：依据实测词边界或语义段边界安排当前单元的镜头与字幕。语义切点落在粗边界内部时，不按字数猜时间；缺少边界、关联失效或镜头错配时报告 `needs_review`。`timeline_complete`、总时长误差和 `semantic_alignment` 分开。新版叙事的正式导出要求语义关联检查通过，仍保留人工审核门禁。
5. `narration_review.py` / `script_writer.py`：本地提取跨段长逐字重复，模型另做逐段新增信息与语义重复复核。有效回扣/强调/兑现须说明用途并引用后段新增推进；不按关键词禁用重复。没有专门语义复核的旧响应不算已完成此项检查。补充“背对画面/镜头”等编辑口吻拦截，继续要求稳定自然称呼，不强行指定身份、心理或因果。
6. `story_pipeline.py`：定向修改反馈明确指向的节点，拒绝顺带重写正确段落；仅改动正文清除事实核验并重新核验，未变段落保留原记录。事实返修后再次复核整稿并可定向修订。增加当前稿件返修入口（页面按钮、`POST /api/story/<project>/revise`、`story_app.py revise`），本轮没有对真实项目执行这些入口。已人工审核的稿件仍锁定。
7. 审核页面展示逐句事件/来源关联及语义同步问题，避免把来源覆盖率或总时长一致显示为观感合格。

### 已有能力与本轮根因

实际缺口：

- 整稿写作只有提炼事实和关系，未传入人物档案；返修只有当前稿、意见及简略提纲，缺少对应事件和身份依据。

- 逐句关联绑定了正文和整话证据，没有绑定段落自己的事件/上下文/来源范围；相同正文的单段操作也会不必要地丢弃旧核验。
- 规划虽在节点内部排序，仍可能接受节点之间交错或倒置的揭示顺序。复核响应异常时也缺少统一的保稿路径。

### 本轮程序和提示词修改

1. `script_writer.py`：写作收到人物档案；返修收到当前整稿、完整规划及仅涉及问题节点的事件和上下文依据。继续只允许反馈指定节点变化。事实整理区分 `narrate/defer/verification_only`，仅供核验内容不送入口播事实；不能以这种内容冒充关键转折已覆盖。共享提示明确具体处境、完整转折链、背景用途和揭示顺序、稳定有据称呼、行动变化与情绪空间，无时长、段数、字数或切镜配额。
2. `narration_review.py`：新增七类结构化内容检查，要求引用当前节点原文和合法事件依据；问题须指向被引用的可修订节点。缺项、伪造引用、无依据判断或不可定位意见不能算完成。原作无相关场面时允许说明不适用；不强造转折。语义回扣须单独引用本段新增理解、情绪或兑现。程序校验引用有效性，语义是否正确仍由模型及人工判断。
3. `story_pipeline.py` / `shot_pipeline.py`：整稿复核绑定当前稿、事件范围、人物、证据和规划，过期或缺项结果不能通过新的文案审核及正式剪辑入口。复核不可用时保留当前稿及明确问题状态，不启动无目标重写。只改动正文的节点清空核验并重查，未改节点保持原样；单段操作返回完全相同正文时也复用原记录。修改后继续复核整稿。
4. `semantic_grounding.py`：关联版本升为2，增加段落事件及来源范围指纹。正文相同但范围变化的旧关联不可复用；历史数据仍可读，不批量改写状态。
5. `narrative_director.py`：模型规划明确背景分类及情绪兑现；本地拒绝节点间交错或倒置原作事件顺序。`fact_checker.py` 强调姓名对应证据及禁止补心理、开枪者和结果。`shot_selector.py` 提示必须检查当前原句，不能提前展示后续揭晓；恢复全图后仍含提前揭晓的结果继续待审核。
6. 审核页面展示七项复核依据说明及复核不可用原因。事实核验、叙事复核、音画关联与最终人工观看仍为不同结论。

1. `story_analyzer.py` 升为分析 v4，沿用逐图积累；按当前人物资料是否可用传入上下文，不按章节号分支。首次或后来新出现的人物均可保持姓名、性别和说话者未知。保存临时 ID、原图来源、识别依据、候选姓名与有据称呼。当前原图附上一来源原图作为连续性参考，不重复提取参考图事件。复用 ID 须说明连续行动、明确称呼、对白或原图对应，衣服相似这一类别不满足结构要求；依据是否真的充分仍需模型看图判断。对应不确定时新建临时记录，保留待核对状态，不自动合并临时 ID。
2. 新增共享 `character_identity.py`，服务现有分析、规划、写作和核验。首次及后续确认共用两项条件：引文逐字来自所引来源的对白/可见文字；另有指向此人物的归属方式、具体说明及来源。不能用未经核对的 aliases 或叙述称呼绕过姓名确认。确有依据的昵称作为独立别名追加，保留正式姓名和昵称各自揭晓位置。

6. 自然口语要求贯穿上述流程及 `story_model.py` 的作者/审稿角色提示：围绕问题、行动、反应与局势变化；让只听声音的观众持续辨认人物；长短句与对白服从讲述。保护重要消息、哭喊、安慰与沉默的空间，不以句长、感叹号数或外貌词频评判，不按词语黑名单批量删改，不以热词、套话或补造心理/身份/主体/因果换取顺口。
7. `narration_review.py` 沿用七类内容检查，将内容格式升为 v2。在 opening/exposition/references/action 中分别要求必要背景、具体关注点与承接、背景作用和位置、听者辨认/身份揭晓/称呼依据、口头讲述的具体判断，引用仍沿用当前正文与事件依据。缺项保持待审，旧报告可读但不能满足当前审核门槛。问题仍经原 `event_id` 指向限定节点返修，修改后重新复核整稿的衔接、称呼、重复、转折、揭晓与兑现。
