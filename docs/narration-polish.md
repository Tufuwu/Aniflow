# 第四阶段：口播编剧重写 v5

本阶段按用户给出的长段漫画解说作为风格标杆重新设计。输入当前稿件，输出有旁白态度、人物反差、包袱展开和配音停顿的整话解说；`ScriptWriter.polish_story()`、`generate/revise` 接口以及下游 `script.segments` 结构继续兼容。

完成后直接进入人工审核锁定，再进行分镜选择与审核、配音试听与审核、时间轴和视频导出。模型逐句原图核验不再作为人工锁定、选镜或导出的前置条件。

## 写法

先读懂整话，再分配铺垫、转折、人物反应、情绪兑现与回扣。对未锁定事件主动进行编剧式重写，压缩发色、站位、持物和拟声清单，使用道夏、同伴、男主、获救男子等稳定称呼。结合交流与行动整理人物对应，C编号与取证式说明不进入未锁定正文。

允许根据上下文补足心理、反应、动作承接、动机、口语化对白、过渡、夸张类比和解说式总结。整话内可以呼应前面的态度、为后面的反差铺垫、压缩已经重复说过的内容。保留本话主要走向与核心冲突，细节表达以故事讲述效果为先，不再按旧版事实逐项收紧。

关键转折展开成完整节拍，例如先讲救援风险，再听到肉罐头，停顿反问，马上问位置，最后由旁白接一句吐槽。普通段落自然推进，关键消息、反问与落点独立成行；不是只在原稿末尾附加一句评论。

三个完整长段示范分别展示环境与处境、救援与罐头的完整包袱、清怪时的队友互动。示例属于写法参考，实际人名、物品与场景按当前素材变化。

## 默认参数

| 参数 | v5默认值 | 含义 |
| --- | --- | --- |
| `humor_percent` | `35` | 0—50整数，解说者调侃倾向；0不主动加吐槽 |
| `suspense` | `medium` | `low`顺畅直叙、`medium`关键转折停顿、`high`强化期待 |
| `narrative_style` | `commentary` | 主动旁白吐槽；也支持 `immersive` 沉浸与 `fast_paced` 紧凑 |
| `length` | `storytelling` | 完整解说，参考原稿90%—110%；以口播效果为准 |
| `analyze_first` | `false` | 可选先设计整话包袱和口播节奏 |

旧的 `concise` 80%—100%、`balanced` 100%—125%、`expanded` 125%—150% 继续可用。目标按未锁定正文计算，只记录参考结果，不自动截断或填充。

旧v4及更早版本自动保存的25%幽默/沉浸/均衡默认组合，在重新生成或重写时升级为v5默认。已经调整过的自定义参数继续保留；v5之后显式选择旧组合也能保留。审核页面同步显示升级后的默认选择。

页面点击“口播编剧重写”生效，或继续用原 `generate/revise` 请求传入 `polish_options`。参数对象省略时沿用该话的设置，部分参数对象以当前默认值补齐。CLI继续使用 `--polish-options` JSON文件。

```json
{
  "humor_percent": 35,
  "suspense": "medium",
  "narrative_style": "commentary",
  "length": "storytelling",
  "analyze_first": false
}
```

## 可选口播导演设计

开启 `analyze_first` 时，先调用 `script_polish_analysis`，设计核心看点、旁白态度和每个事件的 `purpose/setup/payoff/delivery`，再把提纲与原稿一起提供给 `script_polish`。此步是包袱与表演设计，不输出事实检查或收紧建议。默认一次调用即可整稿重写。

模型仍使用已有独立第四阶段路由：`STORY_POLISH_MODEL=openai/gpt-6-luna`，通过 `STORY_POLISH_API_BASE/API_KEY` 调用。前三阶段、配音与后续接口保持原项目行为。运行中的服务需重启加载新代码。

## 输出、锁定与兼容

模型输出完整 `script` 数组，每项仅有 `event_id/locked/text`。事件数量、顺序与ID不变，`text` 允许自然段与短行，不带事件标题。工程上继续保护显式锁定或已审核锁定的原文，逐字保留空白和标点。

旧的稀疏 `segments` 修改响应继续兼容。程序验证JSON结构、数量、ID、顺序、正文与锁定原文后再整份合并；失败不部分应用。移除了角色代号逐事件相等的限制，允许换成自然姓名和称呼。来源与节点映射保留；文字改变后清空过期核验并回到待审核。

提示版本5、风格参数与实际模型指纹参与完成记录。修改参数或更换模型只补做第四阶段，保留已有上游结果和历史稿件。回执 `validation.mode=performance_rewrite` 标识本次口播编剧重写，篇幅记录使用 `advisory_performance_first`。

## 验证

离线测试覆盖结构与锁定、自然姓名替代代码、换行保存、旧默认升级、自定义设置保留、导演提纲、模型路由、失败恢复与上游复用。真实模型实测使用本地大雾题材的13个事件，输出与旧稿单独保存对照。
