# 剧情驱动分镜剪辑：检查与实施计划

## 实际代码检查

- `panel_extractor_yolo.YoloPanelExtractor.detect_image_boxes` 已提供 YOLO 检测和重叠框抑制，原样保留。
- `cropper.crop_panels` 已裁切并输出 `panel_id/path/source_page/width/height`，旧流程包含过滤；新剪辑入口使用 Story Bible 完整证据库，不再次调用破坏性过滤。
- `panel_filter.should_skip_panel` 是内容分类器，不适合作为关键剧情删除条件。保留旧行为，新剪辑层仅参考已有 `panel_type`、边界审核及质量信息。
- `scene_narrator` 按场景分组生成旁白与音频，不具备已审核事件级镜头覆盖约束。新入口直接使用已审核文案，避免重复写稿。
- `compositor` 已支持竖屏、动画及 H.264；新时间轴提供确定的帧数、运动、转场、字幕，新增专用渲染入口，保留旧入口。
- `orchestrator` 的步骤可能通过 `_run_batch_or_single` 遍历章节。新入口独立调用单话服务，不进入批处理路径。
- `StoryBible` 已有原图 SHA256 快照、不可变 revisions、文件锁及乐观版本校验。
- 实际数据：`output/story/first-chapter/Chapter_00001`：82 来源区域，10 段文案，未全部审核。不会擅自审核、改稿或导出此数据。

## 阶段与数据契约

1. 镜头决策：`ShotSelectorAgent` 用 `event_id`、`narration_id=segment_id`、人物、场景（旧数据缺失则为空）、动作、对白召回；可选现有模型复核，引用须通过证据约束。`GlobalShotOptimizer` 在整话候选路径间考虑五项分数和连续性。重复检测结合图像与剧情信息，优先保证事件、规则、因果前提覆盖。
2. 独立版本：`Chapter_00001/editing` 保存剪辑状态，绑定不可变剧情版本；原始文案和输入保持只读。所有修改需传剪辑 revision。人工编辑自动锁定，AI 重跑保留对应镜头组。
3. 时间轴：复用现有 TTS，音频按文本及声音参数缓存；实际解码测量时长，30fps 整数帧分配，字幕时间明确标注为短语估计（不宣称字级对齐）。人工固定时长与音频不兼容时报告冲突。
4. UI：主页面和剧情审核页链接 `/shot-review`，提供完整来源库、逐旁白候选与理由、镜头审核、归一化裁切、运动、转场、时长、音频和视频预览。
5. 验收：覆盖缺失关键剧情、相似图新对白、重复压缩、全局连续性、审核门禁、并发版本、锁定重跑、裁切不改原图、实际音频时长与完整 MP4 导出。仅使用隔离的单话样本，不执行整部漫画批量任务。

## 第一阶段边界

已有库是来源阅读区域，未必每项都是精确的 YOLO 单格，UI 必须展示边界不确定信息并提供裁切。语义召回依赖现有剧情分析质量；旧数据未识别场景时不编造场景。真实章节验收需要人工完成文案审核和镜头审核。所有导出保留独立目录及清单，失败不覆盖已有成片。
