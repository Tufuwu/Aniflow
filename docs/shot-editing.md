# 单话剧情分镜剪辑

改造检查与分阶段计划见 [shot-editing-plan.md](shot-editing-plan.md)。YOLO、原有裁切、旧旁白和批处理入口均保留。

现已增加“配音导演与试听”，支持AI逐句表演计划、三种风格、试听版本和人工锁定，详见 [配音导演使用说明](voice-direction.md)。

## 打开工作台

安装项目 `requirements.txt` 后，运行现有 `python app.py`，点击页头“剧情分镜剪辑”。也可运行 `python story_app.py serve`，打开 `http://127.0.0.1:8081/shot-review?project=first-chapter`。

第一阶段固定使用 `Chapter_00001`，新剪辑流程不会调用章节批处理。项目名对应剧情审核页的项目名。

1. 在文案审核页逐段通过事实核验、人工审核。未全部审核的文案不能进入选镜。
2. 生成镜头候选。默认使用现有 AI 剧情分析的事件、人物、场景、动作和对白证据；勾选“模型复核候选”时，使用现有 `StoryModel` 配置复核排序。模型不能加入来源库不存在的分镜，也不能用无事件证据的相似人物画面替代。
3. 在“完整分镜库”检查全部来源；在“镜头选择审核”查看所有采用、排除理由和五项分数。可采用、移除、前移镜头，编辑归一化裁切、运动、转场、指定时长。必要事件及其递归因果前提必须在对应旁白组内有来源画面。全局事件覆盖不能掩盖某段的局部缺失。
4. 人工修改会锁定本段整个镜头组合，包括已排除镜头。逐段“审核本段镜头”后，AI 重跑完整保留这些组合、顺序、裁切、运动、指定时长和审核理由。“解锁供 AI 重选”才允许重选。编辑已审核镜头会重新进入待审核状态。
5. 在“时间轴”选择 TTS 引擎和声音，生成音频及时间轴。默认是 Edge / `zh-CN-YunxiNeural`。Edge 需要联网；Kokoro、ElevenLabs 需要各自依赖或账户配置。服务不会将失败的 TTS 当作静音成功处理。
6. 镜头全部审核且时间轴已生成后，在“视频预览”导出。成片为 1080×1920、30fps、H.264 / AAC MP4，附 SRT 和包含所有决策的 manifest。失败导出不会覆盖上一份有效成片。

## 数据与保护

原有 Story Bible、审核文案和图像证据保持只读。新数据单独保存在：

```text
output/story/<project>/Chapter_00001/editing/
  current.json                 # 当前剪辑版本指针
  revisions/<revision>.json    # 不可变剪辑历史，绑定 source_revision
  media/audio/<hash>.mp3       # 文本、引擎、声音、语速、音调的独立缓存
  exports/<export_id>/
    video.mp4
    subtitles.srt
    manifest.json              # 来源版本、时间轴、决策、覆盖/同步/完整性报告
    work/                      # 本次导出中间文件，便于诊断
```

人工裁切仅保存相对原始快照的 `[x,y,width,height]` 比例，渲染时读取并派生图像，不保存回漫画原图。所有修改携带剪辑 `revision`，陈旧窗口和并发任务会被拒绝。历史版本只读；新剪辑固定绑定审核时的剧情版本，不迁移或覆盖已有审核数据。

## 选择与节奏

- 候选分数：剧情重要性 25%、旁白匹配 35%、视觉表现力 15%、人物连续性 15%、画面质量 10%。场景连续性、跨事件倒序及整话重复在全局路径优化中额外计分，使用32条路径的束搜索。这是可解释启发式优化，不声称数学最优。
- 质量、对比度、边缘丰富度是视觉代理指标。它们不能删除关键剧情证据。现有数据没有场景字段时保持未知；新剧情分析增加可见场景描述，不会重写旧分析。
- 重复检测结合内容哈希、差异哈希、颜色、宽高比与剧情信息。只有事件、动作和对白都没有新增信息时才按冗余处理；相同图像上的不同对白不能合并为重复剧情。
- 较长旁白可召回更多互不重复的证据画面。实际剪辑时长始终以解码音频的样本数为准，不用字数估计音频时长。镜头按重要性分配整数帧，保留人工固定时长；固定时长不兼容时明确报冲突。
- 转场支持直切和最多6帧淡入；淡入不增加或减去旁白时间。运动支持推进、拉远、四向平移、静止。
- 字幕按短语和实际音频时长分配，当前不是字级强制对齐。字幕、镜头和旁白必须连续覆盖成片。每段音频结尾最多补不足一帧的静音。
- 当前来源可能是包含多个漫画格的阅读区域。UI 展示边界不确定状态，人工审核负责确认裁切仍包含关键动作或对白；程序的覆盖校验基于来源证据，不能判断裁切后的语义是否仍然完整。

## 验收

```powershell
python -m pytest tests -q
node --check static/js/shot_review.js
```

`tests/test_shot_editing.py` 使用独立临时单话来源，不连接云模型，不改已有漫画及审核数据。包括：

- 低质量必要剧情、因果前提、缺失事件及里程碑门禁；
- 相似图无新增信息压缩、新对白保留、全局连续性、长旁白多镜头；
- 模型伪造来源拒绝、版本冲突、并发任务、人工锁定重跑；
- 原图和剧情历史不变、归一化裁切、固定时长冲突；
- 实际波形测量及缓存、逐段同步、字幕完整覆盖；
- 真实 FFmpeg 编码与全片解码，检查 H.264、1080×1920、30fps、AAC、总帧数与导出音轨时长；拒绝截断文件，失败不覆盖既有导出。

本地真实漫画 `first-chapter` 已只读核对82份证据快照，10段文案仍有0段审核通过，保持原状。真实漫画内容的最终选镜质量和节奏验收，需完成这10段人工审核后在工作台继续。
